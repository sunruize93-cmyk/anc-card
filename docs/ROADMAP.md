# ANC Card 下一阶段路线图

更新于 2026-11-14，韩国时间。本文件为未来计划入口；[当日审查](release-review-2026-11-14.md)记录实际交付，[分享版说明](ANC-Card-MVP-分享说明-2026-11-14.md)供非开发人员阅读。下面均为待办，不是已实现承诺。

## 第一阶段：让现在这条链路可靠地重复成功

| 编号 / 优先级 | 要解决的问题 | 做到什么才算通过 |
|---|---|---|
| R01 / 最高 | 长录音与锁屏完整性 | 先解决 64 MiB 输入上限（两小时原始 PCM 约 230 MB），再逐步验证 5、30、120 分钟；原音首尾、时长、字节一致；锁屏全过程无需打开 App 补救。记录耗电、手机/卡空间与保存到结果的时间。 |
| R02 / 最高 | 断连、弱网、重启 | 覆盖卡离开范围、Wi-Fi 断开、后台重启、手机系统回收与用户强退；区分能自动恢复和必须手动操作的情况，不能漏录或重复执行。 |
| R03 / 最高 | 转写超时、空结果和误听 | 每段有成功/失败状态；空结果不得当成无声丢掉；保留原音与人工纠正记录。人名、产品名、否定词、数字、日期、代码文件名建立测试集。 |
| R04 / 最高 | 审计证据与状态文案 | 保存实际批准记录、卡片更新结果与完整执行事件；两轮产物不覆盖。完成后旧的“待验收”摘要不再造成歧义。 |
| R05 / 高 | 失败可见、恢复简单 | 在 App/飞书明确显示卡已保存、正在传、正在转、需要处理；重试同任务且不重复收费/执行的边界可解释；关键失败主动提示。 |

## 第二阶段：减少等待，让团队能实际带出门

| 编号 / 优先级 | 要解决的问题 | 验收方式 |
|---|---|---|
| R06 / 高 | 声音传输与转写提速 | 分开测卡→手机、手机→后台、排队、转写、任务整理、飞书更新。报告常见及最慢情况下耗时；同音频比较 WAV 与 OPUS，同时核对首尾完整和识别质量。先测瓶颈再改，不用单次最快值宣传。 |
| R07 / 高 | 五人五卡和权限 | 每人独立配对及上传凭证；不能看到或确认别人的私密任务，群任务按负责人授权；测两人同时录音、跨卡同名文件、错绑、凭证失效。 |
| R08 / 高 | 出门联网 | 先沿用 Mac；后续为 upload.nestlinker.com 准备常在线后台、可信 HTTPS、监控、备份和成本限额。蜂窝网络完成同源验收后才能称脱离同 Wi-Fi。 |
| R09 / 高 | 远程 Personal Agent 正式接入 | 把已通过的 Grok 邮箱实验接到正式台账及负责人确认；签名派发、过期/撤回拒绝、原卡回写、回执丢失恢复、同会话续跑。邮箱通知本身不是授权。Claude Code 另行验收。 |
| R10 / 中 | 存储与清理 | 后台原音、转写及文档均可靠保存且核对成功后，才考虑清理手机/卡旧文件。先提供预览和人工确认，覆盖删除回执丢失、并发新录音；默认不删。 |

## 第三阶段：理解更准确，录音时也能协作

| 编号 / 优先级 | 能力 | 具体边界与验收 |
|---|---|---|
| R11 / 高 | 多语言转换 | 先测中、韩、英以及一句话混用；分别评估听写和翻译。保留原文、译文、原音时间，专有名词可纠正。人名、金额、否定词不能靠流畅译文掩盖错误。开放模型切换前用同一批录音对比质量、延迟和费用。OpenAI 替换百炼仍待办。 |
| R12 / 高 | 任务判断与派发 | 区分聊天、建议、承诺、已接受任务；缺负责人/截止时间时提问或留待核对。同一件事合并，改口推进版本，撤回停止未完成执行。14 个 Coffee Chat 场景先形成真实评测，不把测试集存在当作模型已通过。 |
| R13 / 后续 | Streaming context：边聊边同步 | 先验收真实卡持续推流、锁屏和断连后补齐，再做分段转写。群中只维护一份更新中的摘要，标明“讨论中/待确认/已确认”；片段不够时暂缓派发，不能把临时想法直接执行。会后用完整录音统一核对。 |
| R14 / 后续 | 实时改口和撤回 | 测“Eric 做→改为 Zoty→先别做”以及跨段补充、重连重复片段。未确认不执行，旧版本结果不覆盖新决定；已经产生外部影响的操作要报告并人工补救，不能假装可自动撤销。 |

## 第四阶段：越用越懂公司

目标不是把每句话永久保存，而是把**经过核对、确实有用的经验**沉淀下来。

1. **个人词库和偏好**：姓名、品牌、常用缩写、常用表述；纠正一次后，在后续录音中验证是否更准确。个人偏好只对本人有效，团队词表需要共享范围。
2. **企业知识库**：产品事实、项目约定、客户沟通记录、已有决定、常见问题和工作模板。每条记住来源、谁核对、何时生效、适用范围；过期内容可撤销，不能把一次误听变成公司事实。
3. **任务结果反馈**：记录原建议、实际负责人、修改原因、返工原因和验收结果。先每周生成改进建议，由人确认后调整流程；不让系统私自扩大权限。
4. **下一次真的用上**：给相似任务时引用已核对的旧经验，并能回到出处。用保留的测试题比较改进前后；不能只展示“已记住”。
5. **衡量是否更好用**：误派率、遗漏率、人工改动次数、返工率、完成时间、每次会议费用；同时检查新人是否能理解、不同成员是否被错误地固定分工。
6. **纠错与隐私**：个人与团队记忆分开，录音告知、访问范围、保留时间、导出/删除入口明确；删除或改正的知识不能继续被推荐。重要决策保留人工确认。

## 平台和适配计划

- **Android**：复用后台上传和去重约定，另做蓝牙客户端、后台传输和权限界面；测试不同品牌省电限制，不能照搬 iPhone 后台行为。
- **更多 iPhone**：不同系统、不同机型、低电量、锁屏/重启/强退、蓝牙耳机同时使用。现工程最低目标 iOS 17 不等于已测遍 iOS 17 起的所有版本。
- **Windows / macOS / Linux**：区分开发调试工具、手机客户端和后台。Windows 现有协议工具不等于 Android App；云端需替换当前依赖 macOS 钥匙串和系统音频工具的部分。
- **卡的差异**：五卡固件、文件命名、时区、电量、存储、断连与分包行为逐张登记；韩国时间校时成功不能外推所有固件一致。
- **使用与分发**：目前逐台安装调试版。之后再决定 TestFlight/正式分发、升级迁移和凭证轮换，减少逐台维护成本。

## 建议下一轮只做三件事

1. 同一人、同一卡先把 5 分钟及断网恢复跑稳，留下可复核的完整记录。
2. 记录各段耗时，用同一录音比较传输/转写策略；保留质量底线。
3. 邀请第二位成员独立完成一次，从首次安装到负责人验收，找出真实上手障碍。

多语言、实时同步、知识库可以先收集样本和需求，但每轮只挑一个明确能力动手，避免再次让手机、后台、执行器同时换版本而无法定位问题。
