## 限制与检查方式

云端脚本先持久化 reserved 状态，再启动 Codex；跨进程 flock 保护执行入口。失败或崩溃后保留状态，重复投递不会自动重跑。这是保守的至多一次启动策略，**不保证失败任务最终完成**。生产重试需要先核对已有进程与产物，再显式创建新尝试。

使用 workspace-write、never approval、禁工具网络、禁网页搜索、240 秒上限。云端独立探针证实目标目录可写、相邻目录不可写，DNS 和 IP 直连均被拒绝。最终两文件范围由执行后的文件清单检查；不是文件级写入白名单。测试不构成对任意恶意任务的完整安全证明。

独立验收使用回传文件实际执行五个用例：混合类型、空数组、null、undefined、小数。基础文档检查只检测函数名和 null，不宣称覆盖所有文档语义。人工另核对本次实际 README 示例。收到的代码在本机禁网络、禁写入且不允许子进程的检查环境运行。

本机离线去重测试 2 项通过，覆盖并发重复、后续重复、绑定不符、过期、CLI 不可用。它们使用假 CLI，和上面真实云端证据分开计数。桥接验收曾用一个正确夹具和一个错误实现验证可通过/可拒绝；不将夹具算真实任务。

## 这次还没有证明什么

- 这是**专用测试卡**，不是原录音任务的续跑；没有把既有任务换到远端。
- 执行范围由 Eric.s 在 Codex 对话中授权，本轮没有验证新的飞书按钮授权。
- 尚未接入正式 TaskStore、outbox、负责人改派/撤回和生产验收状态机。
- 邮件入口还依赖 Grok routine 的筛选；生产应加机器验证的签名、版本与失效时间，不能让任意邮件成为执行授权。
- 临时 Webhook.site 仅收合成代码与运行元数据，不是生产回传服务。下一阶段应换为自有 HTTPS 回调、签名验证、持久化收件箱与重放防护。
- Mac 仍承担本次独立验收及飞书 API 回写。**没有验证 Mac 关机后的完整闭环，也不能据此把 Grok 云电脑当作常驻公网服务器。**
