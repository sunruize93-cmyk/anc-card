# Grok Bot 邮件唤醒与外部回执实测

日期：2026-11-14，韩国时间。范围：单个合成消息，邮件输入、HTTPS JSON 输出；未接 Codex、真实录音或 ANC 任务执行。

## 结果

**单次自动闭环已通过。** 用户完成首次 Bot 邮箱开通后，测试邮件唤醒临时 routine；Grok 云电脑向独立测试接收端发出 POST，接收端记录的 testId、nonce、status 三字段与预期完全相同。发送测试邮件后，没有再发聊天消息催跑，也没有人工批准或代发结果请求。

Mac 主服务与上传网关保持原进程运行，本轮没有重启或修改后台。

## 实测顺序

1. 打开现有 Grok Bot，完成已下载的软件更新；只读检查邮箱及事件触发能力。
2. 账号原先没有 Bot 自带邮箱。准备具体地址后，用户亲自保存/开通；UI 显示“已连接”。
3. 创建“ANC 邮箱唤醒单次测试”，仅匹配用户的指定 Gmail 发件人和专用 `+anc-test` 收件别名，要求邮件认证通过。
4. 指令限定一个 testId、UUID 格式 nonce、固定 HTTPS 接收地址；不执行来信命令、不跟随来信链接、不读取其他邮件、不发回复邮件。
5. 通过已连接 Gmail 发出一封合成测试信。随机 nonce 仅通过这封邮件交给 Grok，没有提前放入 Grok 聊天。
6. 独立接收端于 **16:50:00 KST** 记录 `POST`、`Content-Type: application/json`、106 字节请求；内容与本机预期逐字段匹配。
7. Grok UI 随后出现“已禁用 例行任务”，表明测试监听已收尾。

16:50:39 的最终回复自报邮件 16:49:18 送达、16:49:23 触发、HTTP 200；UI 的监听开关实际为 off，状态“已暂停”。邮件送达/触发时间来自 Grok 报告，接收端 16:50:00 与请求体来自独立 API；按两端记录，送达到回执约 42 秒，不作为长期时延保证。

## 证据与判定

- Gmail 发送接口返回消息 ID 和 SENT 标签。
- 外部请求记录 ID：`d00e83d9-58ab-4694-91d9-788e1a02ac13`。
- 接收 JSON 的精确匹配验证为 true；验证程序只查询接收日志，没有向接收地址发送测试结果。
- 收尾查询共看到两个 HTTP 请求：一个有效 POST 回执，以及 16:50:37 来自 Grok Bot 客户端 User-Agent 的无正文 GET。GET 的具体触发原因未确认，不计作回执或重复执行；有效 POST 数仍为一。正式接收器必须校验方法与内容，不能把任意访问都当成功。
- Grok 的“正在工作”与后续“已禁用例行任务”状态来自实际 UI，不只引用模型口头结论。
- 原始发送回执、接收记录、匹配结果与测试配置保留于本机 `.anc-data/field-20261114/grok-mail-smoke/`。公开文档不附邮箱身份、完整临时入口或 nonce。

独立接收端使用 Webhook.site 的临时测试入口，设置一小时过期、最多保留 10 条历史请求、关闭 Custom Actions。它只接收合成 JSON，未连接 Mac 网络或任何生产资源。不能用于真实录音、密钥或生产任务结果。

## 边界

- 通过的是 **邮件唤醒 → HTTPS 回执**，不是自动回邮件；没有绕过 Grok 自带邮箱的发送审批。
- 本次明确限定的数据外发没有弹出审批；不代表所有未来任务或工具调用都能自动放行。
- 邮件触发器未提供原生截止时间，截止检查写在指令内；此次通过实际禁用监听结束测试，不把指令中的截止时间视为系统强制 TTL。
- 单次成功不证明长期运行、重复投递幂等、断连恢复、执行授权隔离、远程 Codex 会话持久化或稳定服务器托管。
- 当前实测只证明远程执行接入的消息通道有可用基础。Mac 后台仍是唯一台账与飞书主 bot 所在地。
