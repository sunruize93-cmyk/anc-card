# 上传连接与故障恢复：11 月 15 日第二轮

## 手机联调暂缓，已有成果保留

用户决定等有数据线后再处理手机连接，先推进独立的软件任务。本轮没有要求继续切热点，也没有安装新版 App。

Mac 端已完成：

- 上传网关切到当前局域网地址，换上与地址匹配的证书；沿用设备身份、凭证和 CA。
- 严格 HTTPS 校验与鉴权健康检查通过，网关保留原有 16 条上传回执。
- 主后台没有重启，转写配置和飞书连接检查通过。

手机端仍未完成：

- 手机 IP 可 ping 通、设备通信端口可连接，但 Xcode 仍显示无线设备不可用；不能据此断言是校园网阻断。
- 新地址、凭证有效期与 CA 配置尚未写入现有 App。
- 5 分钟真实录音未开始，手机到 Mac 的新连接没有验收。

有数据线后，先向现有 App 写入两份配置文件并重开 App，保留原有配对、录音和状态；这一步不需要先升级 App。届时必须重新检查 Mac 当前地址，不能继续照抄今天的地址。旧版 64 MiB 上限可容纳约 9.6 MB 的 5 分钟、16 kHz 单声道 PCM16 WAV；实际卡格式与最终字节数仍需核对。

## 已补的自动化验收

运行：

```sh
npm run verify:upload-recovery
```

三项测试全部通过。新测试使用五分钟合成信号、真实 HTTP 传输、SQLite 持久化和独立网关子进程；转写返回预设文字，飞书用本地替身，不会消费百炼额度或发到真群。

| 故障 | 验证结果 |
|---|---|
| 手机只传一部分便断开 TCP | 不完整文件不进入主后台；不会创建录音或调用转写 |
| 主后台已保存，网关尚未拿到回执便被 SIGKILL | 恢复时本地回执确实为空；相同文件重试能取回重复回执 |
| 网关重开后凭证过期 | 返回 401，不转发到主后台；显式续期后可继续 |
| 回执持久化后再重启网关并重传 | 保持一条回执、一份录音、一个录音任务和相同结果卡投递标识 |
| 同一客户端录音 ID 换成不同哈希 | 返回 409，不污染原有绑定 |
| 飞书已创建卡但回复丢失、更新暂时失败 | 已有投递测试确认重试沿用相同投递标识及原消息 ID |

新故障场景下完整原音哈希保持一致，十个 30 秒片段只识别一次，时间覆盖到 300000 毫秒。第一次测试修正了夹具中的任务计数断言：任务列表含内置演示任务，应只计本录音来源；没有将其当作业务缺陷。

这里的“重启”包含对隔离网关进程的实际强制结束；不是手机系统回收、手机断网或真实飞书验收。主后台持久化使用真实录音队列模块，测试 HTTP 层是最小导入适配器，不替代正式 HTTP 路由已有测试。当前业务代码没有因这轮测试变更。
