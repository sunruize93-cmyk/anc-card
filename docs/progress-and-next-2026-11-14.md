## 主要痛点与分工

1. **锁屏唤醒是第一阻塞。** iPhone 线定位保存通知/系统唤醒，分别记录前台、锁屏、强退；必须在正常锁屏期间无需重开 App 才通过，不能用无限后台轮询冒充。
2. **长音频传输效率。** iPhone 线已提交同一 72.72 秒录音的真实下载基准：WAV 2,327,084 字节/28.17 秒，raw OPUS 145,520 字节/2.14 秒，体积约 1/16、耗时约 1/13。解码样本约 72.75 秒，需要继续核对编码延迟/有效时长和时间点；后台 raw OPUS 严格上传与真实解码已实现并于15:48 KST部署，隔离测试通过，仍待新OPUS录音端到端验收；保留 WAV 兼容，暂不接受外部 Ogg 输入。现在不要按一分钟样本简单外推两小时；后台当前 WAV 64MiB 约35分钟，长会议仍需分段/压缩方案。
3. **安全清理尚未落地。** 最近五条规则目前只预览；真实文档/原卡成功回执是必要条件，但还需归属、历史保护、当前版本/回听需求与删除确认。不删除未完成/歧义待核对原音。本轮没有删除任何音频。
4. **消息时序与恢复。** Zoty 本轮只离线修 G2 d 事件丢失及 G3 c 列表错位，交代码差异和可供 Swift 复用的 JSON 场景；iPhone 侧按自己的分发结构融合，避免盲抄 Windows 修复。
5. **知识沉淀和业务准确性。** 我方下一步把这次真实确认、产物和原卡证据接入独立审计；再用 Coffee Chat 的改口/改派/撤回测试集测语义，而不是只验证固定正则。最后实现“人工纠正→版本化知识→下一轮检索引用”。
