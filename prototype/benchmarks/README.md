# 可控并行转写基准

本目录只测试 standard SpeakMode/百炼转写。默认生产设置保持串行；只有显式设置 `ANC_ASR_CONCURRENCY=2` 或 `4` 才改变新启动实例。诊所模式始终串行。没有多录音并行，每个录音内的片段使用同一上限。不同进程不会共享全局限流器。

## 离线检查

```sh
npm run verify:asr-parallel
npm run verify
```

覆盖乱序完成但按原文顺序返回、并行上限、缓存有空洞、首次错误停止派发、在途请求结束后才返回、保留首个失败原音范围、关闭时取消、重开数据库后只恢复未成功片段。原有超时只重试一次，鉴权失败、空文本、限流不无限重试。

## 真实百炼对比（会产生 API 用量）

macOS 下使用自制中文文本和系统 Tingting 语音，不读取客户录音。使用已配置的 SpeakMode 与钥匙串身份，不在脚本中放 Key。运行目录必须隔离，不能指向生产数据。

```sh
node prototype/benchmarks/asr-parallel.mjs .anc-data/asr-benchmark-NEW --prepare-only
node prototype/benchmarks/asr-parallel.mjs .anc-data/asr-benchmark-NEW --run-cloud
node prototype/benchmarks/summarize-asr-parallel.mjs .anc-data/asr-benchmark-NEW/results.json
```

只有 `--run-cloud` 会调用云端，准备音频不收费。已有 results.json 时拒绝再次运行，避免重复计费和覆盖证据。中断后的部分结果保留；完整比较需要重新使用新目录并计入新用量。不要对失败批次无限重跑。

三条音频固定后，比较三轮，顺序为 1→2→4、2→4→1、4→1→2；每轮也轮换样本顺序。每次运行创建独立数据库，不复用转写缓存。只改变 worker 数，分段算法、模型、语种和请求超时不变。基准串行运行每个样本，避免把多录音同时运行混入效果。

计时从录音导入开始到转写及任务入库完成，包含音频转换、调度和本机 SpeakMode 子进程；不包含卡到手机、手机上传、飞书或摘要模型耗时。记录样本 SHA-256、每段原音时间与哈希，结束后检查完全一致。TTS 的声音版本可能随 macOS 改变，跨电脑重建音频应作为另一批次，不能直接声称字节相同。

## 准确性口径

- 字符错误率：NFKC、转小写、去标点及空白后的编辑距离 / 参考字符数。数字格式差异仍可能计作错误；不是语义准确率。
- 关键项：预先固定的负责人、日期金额、否定与改口文本核对；数字允许中文/阿拉伯数字写法。不得在看到输出后放宽正则使结果更好看。
- 人工复核：保留完整参考和每次输出，检查偏差是否来自误听、格式或关键语义。串并行输出一致仍不等于输出正确。
- 三条短 TTS 录音仅验证这个样本集合，不能推广到两小时会议、噪声、口音和多语混说。

报告汇总每轮三条音频耗时之和，取三轮中位数；同时保留全部轮次。不能只挑最快的一次。发生请求失败、时间点/哈希不符、缓存污染时停止，不把缺失样本算作成功。
