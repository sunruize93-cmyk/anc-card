ANC Card 是五人团队的录音与任务台账原型。导入音频后，原文件先与排队记录一起写入 SQLite。后台调用 SpeakMode 的文件转写工具，把识别到的明确分工写入带出处的任务台账。点击时间范围可回听原录音，行动项初始状态为「待核对」。

最新[协作构想与验收顺序](docs/architecture.md)：录音卡经 iPhone 自动上传后台，使用自有 SpeakMode＋百炼处理，再将任务交给飞书与对应 Personal Agent，保留验收反馈并沉淀团队知识。iPhone 短录音自动同步已完成上述现场验收，长会议、更多设备和企业知识反馈仍待完成。

扩展测试按[逐步测试清单](docs/arrival-acceptance-checklist.md)验收，包含操作、通过标准、证据记录、失败排查及长录音与五人扩展条件。

## 本机运行

需要 macOS、Node.js 22.13+、Rust stable、Git 和 Xcode Command Line Tools。在项目根目录执行以下命令，安装固定版本的 SpeakMode 文件转写工具，然后启动原型。

```bash
npm ci
sh prototype/scripts/setup-speakmode.sh
node prototype/server.mjs
```

打开[本机原型](http://127.0.0.1:4785/)，展开「配置 SpeakMode 的阿里云转写」，选择 API Key 所属的北京或新加坡地域，填写百炼 Key 并保存到登录钥匙串。也可在终端配置，输入时会隐藏 Key。

```bash
sh prototype/scripts/configure-speakmode.sh
```

配置助手使用 SpeakMode 自己的配置和凭据接口。其配置数据库默认位于 `~/.local/share/anc-card/speakmode/config.sqlite`，密钥保存在 SpeakMode 的登录钥匙串条目中。保存配置后，导入一份 WAV、M4A 或 MP3 开始处理。音频分段会发送到所选地域的阿里云。

需要创建 Key 时，可参考[百炼 API Key 配置说明](https://help.aliyun.com/zh/model-studio/get-api-key)。

### 选择转写模式

`npm start` 以基础模式启动。后台按停顿切分音频，使用 `qwen3-asr-flash` 的自动语种模式转写。每个新分段中的 `requestedLanguage: "auto"` 记录调用时的设置。

多人商谈可以由同一个本机程序 `clinic_session` 完成话轮划分与原声转写。在已有基础工具的 Mac 上运行：

```bash
sh prototype/scripts/setup-speakmode.sh --clinic-only
npm run authorize:clinic
npm run start:clinic
```

授权命令只尝试读取当前配置对应的 SpeakMode 钥匙串条目，在本机进程内立即释放凭据，不处理音频或发出网络请求。在 macOS 对话框里核对申请程序为 `clinic_session`、条目为 `SpeakMode.Cloud.v1`，选择「始终允许」。后续分段和转写沿用同一个可执行文件的身份，后台禁止授权弹窗。钥匙串锁定、所选地域的密钥尚未配置或重新编译导致签名变化时，页面会显示具体失败步骤及 `clinic_keychain_access_required`。处理后可在原录音上点重试。

诊所模式先将音频段发送至 `qwen-audio-3.1-asr-flash` 判断话轮，再按得到的范围切取原声，交给 `qwen3-asr-flash` 转写。两步都使用所选阿里云地域，分别产生模型用量。请仅导入和回听已获准处理的录音。在转写全文中点击时间范围，可从原声对应位置核对报价、否定词和预约时间。

在 Apple Silicon Mac 上，可以用门诊词表和本地 Qwen3-ASR-1.7B 完成第二步：

```bash
sh prototype/scripts/setup-clinic-local.sh
npm run start:clinic:local
```

该模式沿用同一 `clinic_session` 的云端话轮划分和钥匙串授权。首次安装下载固定版本的本地模型，运行时只将音频发往所选阿里云地域做话轮划分，随后在本机识别每段原声。每条录音保存导入时选定的工作模式，重试时继续使用同一模式。转写保留原语言文字，模型附带的语言名称可能出错；复核报价请点击回听，并以院内价目与商谈师核对为准。

「片段组 1 · 声音 1」是该片段组内的匿名编号；下一组中的相同号码可以属于不同的人。当模型没有给出可用编号时，页面只显示转写和回听范围。人员身份及项目决定由经办人核对。切换模式后，已经完成的录音仍保留原先结果。

## SpeakMode 接入方式

安装脚本拉取 SpeakMode 的固定提交 `6ba4432d91727d300ba6f3e4b1a9e29d37064a64`，编译其原有 `file_asr_lab`。ANC Card 在运行时直接调用该可执行文件，读取其 JSONL 回执，校验音频 SHA-256、样本数、完整状态、模型和处理批次，再写入台账。配置助手调用 SpeakMode 的 Store 和 credentials 接口。

基础模式固定使用阿里云 `qwen3-asr-flash`，输出整段文字。ANC Card 先转换为 16 kHz 单声道 PCM16 WAV，按停顿切成最长 30 秒的音频段，保留每段在原文件里的样本偏移。识别结果绑定到该段的起止位置，页面显示「分段回听」。

这个时间范围覆盖整段音频。持续讲话达到 30 秒会强制切段，边界可能落在句中。识别和行动项提取均需回听核对。对于后续长会议扩展，可评估支持原生时间戳的文件转写模型，具体能力见[阿里云语音识别文档](https://help.aliyun.com/zh/model-studio/asr-model)。

每个成功分段都会独立保存。失败重试和重启会复用已保存的分段结果。进程中断时，尚未落盘的远端请求可能已经被供应商处理，再次提交可能产生重复调用费用。

## 自制音频与验收

生成约 29 秒的普通话样本，再从页面导入。

```bash
sh prototype/scripts/make-sample.sh /tmp/anc-card-sample.wav
```

离线验证会实际生成音频、进行转换和分段，再使用明确标注的 SpeakMode CLI 协议夹具验证持久化链路。

```bash
node prototype/verify.mjs
```

已验证并发重复导入只入队一次、分段转写失败后重试、已完成分段复用、SIGKILL 后自动恢复、台账与分段证据绑定、原音频逐字节返回和区间读取，以及完成台账在重启后保持条目 ID。损坏回执和音频哈希不符会被拒绝。SpeakMode 上游 `file_asr_lab` 的 7 项测试也已通过。

真实云端验收在配置 Key 后运行以下命令。它会将自制音频通过 SpeakMode 发给阿里云，核对两条行动项及其证据位置。结果会保留在当前台账中。

```bash
node prototype/verify-live.mjs
```

## 统一任务台账和飞书确认

录音中的每条行动项使用原有条目 ID 进入执行台账，保存原录音、分段范围、识别原文、负责人、验收项、确认记录、建议版本、Codex 会话和每轮快照。转写结果与首次任务创建在同一数据库事务内完成。旧录音会自动补建执行台账，重复导入保持同一任务。

早期执行方案为「两轮接口验收」，适用于录音中明确包含接口示例和 429 要求的任务。当前另有 `/agent` 入口，可填写待确认的文件范围和验收要求，负责人确认后执行；任务方案仍需人工核对。首轮确认后交付可运行示例和说明，独立验收得出缺口，再生成 429 单次重试建议。次轮确认后通过 `codex exec resume` 继续原会话，并保留首轮代码和验收证据。此方案用于验证协作闭环，其他类型任务可先保留在待核对状态。

在本机页面展开飞书配置，填写企业自建应用的 App ID 和 App Secret，保存后读取机器人已加入的群，选择测试群和确认负责人。应用需开启机器人能力，并具备发送消息、更新消息卡片、读取群和群成员的相应权限。在回调配置中添加 `card.action.trigger`，使用长连接接收回调。具体配置见[飞书官方回调文档](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)。

可用以下脚本生成包含接口交付要求的普通话录音，再从页面导入并准备执行方案。

```bash
sh prototype/scripts/make-execution-sample.sh /tmp/anc-execution-sample.wav
```

准备后，机器人向选定测试群发送确认卡。只有绑定负责人能确认，服务同时校验应用、群、原卡片、任务版本和建议 ID。确认在落盘后入队，执行异步推进。后续状态按同一消息 ID 更新原卡片，卡片发送或更新失败会独立重试。首发使用稳定的消息去重键，供应商去重有效期以其接口约定为准。

App Secret 保存在本机数据目录的 `feishu.json`，文件权限为 0600，Git 会忽略该目录。录音回听地址目前供本机页面使用，飞书卡片显示来源文件和分段时间范围。执行产物保存在数据目录的 `tasks/<task_id>/`。服务重启会恢复排队和待确认状态，执行中断会等待负责人恢复原会话。

任务与卡片回调检查可运行以下命令。

```bash
node --test prototype/tasks.test.mjs
```

2026-11-07 本机实测真实 Codex 两轮执行从 2/3 达到 3/3，两轮会话 ID 一致，首轮快照和完成记录在服务重启后保留。飞书 SDK 回调结构、负责人及版本校验、重复点击去重和待确认状态恢复已通过离线检查。真实测试群的按钮回调与原卡片更新仍待实测。

### 飞书音频文件入口

绑定测试群后，订阅 `im.message.receive_v1`，为应用开通接收群消息与获取消息资源的权限并发布。为自动接收没有 @ 机器人的文件消息，需要相应的群消息读取权限。以应用后台列出的权限及可用范围为准，可参考[消息事件文档](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。机器人只处理配置中指定测试群的用户附件，其他群、单聊、机器人消息和无关文件均忽略。该群的 WAV、M4A、MP3 附件会进入百炼转写，测试群成员需知悉这一用途。

手机将录音 App 导出的音频作为文件发到群里。事件元数据先写入同一个 SQLite，再异步通过飞书消息资源接口下载音频，导入现有 SpeakMode 队列。相同消息事件不会重复入队；相同音频即使换一条消息发送，也复用音频哈希、转写和任务 ID。下载与结果回写失败会退避重试；重启后继续未完成收件。

机器人在原音频消息的线程中创建结果卡，排队、转写、失败和完成状态更新同一回复。完成卡含分段原文、原音频时间范围、负责人、截止时间及同一任务 ID。长结果会截短展示并明确提示，完整内容保留在本机台账。ASR 失败可从本机页面重试，卡片随后更新。此入口不调用飞书转写，也不会因收到录音就自动执行 Agent 任务。

首版限制为 64 MiB 以内的 WAV、M4A、MP3 文件，原生飞书语音消息和裸 OPUS 暂不支持。服务目前依赖运行中的 Mac、SpeakMode 工具和登录钥匙串。无需个人电脑开机的使用方式还需要部署常开后端并适配这些依赖。录音卡的 iPhone 无线接入依据与兼容限制见[硬件接入核对](docs/recording-card.md)。

2026-11-11 已通过音频入口的官方 SDK 事件形状、群范围校验、消息去重、持久化收件恢复、同音频复用、下载与回写重试、原线程卡片更新和超限提示的离线测试。它们使用传输夹具；当前没有配置飞书应用，真实群收件、资源下载、回写和卡片确认仍待实测。

## 参数与数据

- `ANC_SPEAKMODE_BIN` 可指定 `file_asr_lab` 可执行文件的绝对路径。
- `ANC_SPEAKMODE_CONFIG_DB` 可指向已有 SpeakMode 的配置数据库。复用配置时需要其中的阿里云地域与登录钥匙串凭据相匹配。
- `ANC_DATA_DIR` 可指定独立录音数据目录，默认为仓库内的 `.anc-data/`。
- `ANC_PROTOTYPE_PORT` 默认为 `4785`。服务监听 `127.0.0.1`，同一数据目录同时只允许一个服务打开。

原录音、转写、分段检查点和任务台账保存在本机数据目录，Git 会忽略该目录。每份音频上限 64 MiB。现有提取规则针对「由某人负责某事」一类明确表述，可保留同一分段中的「截止时间是……」。

旧版台账可继续读取，并在页面标记为「旧版本机转写」。实卡短录音已完成 2026-11-14 所述验收，真实长会议仍待验收。页面底部保留使用同一持久化执行服务的 [Codex 同会话续跑演示](prototype/README.md)。
